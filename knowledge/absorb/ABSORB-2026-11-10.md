## 4. 代码修复（本仓库自身的问题）

### 4.1 `patches/guard-hooks.patch`（高危）

`planner`（`agent/planner.go:392`）与 `mainagent`（`agent/mainagent.go:133`）都通过 `actool.DefaultTools()` 拿到了 Bash，但 `agentcore.Options` 里**从未装配 Hooks** —— 全仓唯一的装配点是 `server/engine.go:1055`（worker）和 `agent/chat.go:166`（chat）。

后果：数据库里 19 条内置拦截规则、人工审批、LLM 兜底评审，对这两个角色的每一次 shell 调用都不生效；而 planner 每轮都读目标侧内容（facts / traffic 摘要），一句注入即可直达本机 shell。

补丁做了三件事（与 `ChatAgent.SetGuard` 同构）：

```
agent/planner.go       + import guard, + guard 字段, + SetGuard(), + opts.Hooks
agent/mainagent.go     + import guard, + guard 字段, + SetGuard(), + opts.Hooks
server/task_llm.go     + pl.SetGuard(t.Guard) / main.SetGuard(t.Guard)
```

应用：

```bash
git apply patches/guard-hooks.patch
go build -tags embedui -o artex ./cmd/artex   # 必须编译验证
```
