## 一、判定标准（写结论前先分类）

- **实测**：观测**带对照**（对照组给出不同结果），可在任意时点独立复现。
- **推断**：由**单点观测 + 经验假设**推出。**只要存在一个同等合理的替代解释且未排除，就必须标注为推断。**

## 二、强制自检三问（每写一条结论前问自己）

1. 这条结论的证据是**单次观测**还是**带对照的观测**？
2. **是否存在第二个假设也能完全解释该观测？**（"目标用的就是同款技术栈"是最常见的第二假设）
3. 我有没有做**能区分这两个假设的测试**？没做 ⇒ **写"推断"，不得写成定论**。

## 三、实战例证一：把"前缀拦截"误读为"文件受保护"

- **初判**：`/static/dump.sql`、`/static/api/swagger.json`、`/static/api/swagger.yaml` 均返回 401 ⇒ 记成"存在受保护的敏感文件（数据库导出 / API 文档）"，并据此排期投入。
- **对照实验（三条探针）**：
  - 随机不存在的同前缀资源：`/static/zzz_nonexistent_12345` 与 `/static/zzz_nonexistent_12345.html` → **401（338B）**
  - 框架/面板自带、必然存在的资源：`/static/css/style.css` → **401**；`/static/css/`、`/static/js/`、`/static/img/`、`/static/api/` → **全部 401**
  - 同前缀但不带斜杠：`/static` → **404**
- **修正结论**：**401 是"整前缀级认证"**，凡以 `/static/` 开头一律 401 ⇒ **完全不能作为"文件存在"的证据**。旁证：`/data/default.db` → 302→/login、`/xxx_nonexist_zz/` → 404，说明该 401 与路径内容无关，只与前缀绑定。
- **附带发现**：同一路径在 443/80/888 端口均为 404 ⇒ 该前缀**只存在于 8888 端口**，跨端口比对本身也是一条有效对照。

## 四、实战例证二：用"技术栈风格"推断"存在独立应用"

- **观测**：返回的 401 页面是 Werkzeug 默认样式 ⇒ 推论"8888 = 宝塔主体 + 一个被单独代理的 Flask 应用"。
- **漏洞**：**宝塔面板自身就是 Python/Flask(Werkzeug) 栈** ⇒ 同一证据**完全支持**"该 401 由宝塔自己的鉴权分支产生，不存在第二个应用"。**未做**后端标识头 / 上游端口 / 独立路径对比去排除后者。
- **处理**：**主动降级为推测，并落库界定**（哪句是实测、哪句是推断），避免被后续报告当定论引用。

## 五、最小对照实验模板（可直接套用）

```
# 1) 目标路径
curl.exe -s -k --path-as-is -o NUL -w "%{http_code}:%{size_download}" "http://TARGET/prefix/SUSPECT"
# 2) 必然不存在的同前缀资源（随机名）
curl.exe -s -k --path-as-is -o NUL -w "%{http_code}:%{size_download}" "http://TARGET/prefix/zzz_nonexistent_12345"
# 3) 必然存在的同前缀资源（框架自带 css/js）
curl.exe -s -k --path-as-is -o NUL -w "%{http_code}:%{size_download}" "http://TARGET/prefix/css/style.css"
# 4) 同前缀去掉斜杠 / 换端口比对
curl.exe -s -k -o NUL -w "%{http_code}:%{size_download}" "http://TARGET/prefix"
```
判读：**若 1、2、3 的响应一致 ⇒ "受保护文件"的结论作废**（那是前缀行为）；**若 2 与 1/3 明显不同 ⇒ 才支持"该资源存在且受保护"**。

## 六、为什么这条纪律值得进知识库

红队里最贵的不是漏报，而是**把推断写成实测后引发的连锁误判**：指挥者会据此排期、投入人力、写成报告，最后被一个随机文件名推翻。**一次对照实验的成本是 1–3 个请求，收益是整队的方向不被带偏。**
