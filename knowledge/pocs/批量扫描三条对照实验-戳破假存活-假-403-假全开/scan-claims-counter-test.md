# 批量扫描的三条对照实验（戳破假存活 / 假 403 / 假全开）
# 原则：任何"批量扫描结论"都必须配一个能把它推翻的对照实验，否则不得写进报告与派活清单。

## 对照 1 —— 假存活（-Pn 把死 IP 一律判 up）
# 现象：nmap -Pn -sT 对整段报 "Host is up"，无法区分死活。
# 对照：另跑一遍 -sn（ping sweep），以它的结果为准。
nmap -sn --max-rate 200 <CIDR> -oN runs/sn-<seg>.txt
# 实测（tgt9942 靶标 203.0.113.69/24）：-Pn 报 256/256 up；-sn 实测仅 147 存活 —— 虚高 74%。
# 教训：-Pn 只用于"跳过主机发现去扫端口"，绝不能用来数存活主机。

## 对照 2 —— 假 403（端口级白名单伪装成应用拦截）
# 现象：某端口（如 888）大批返回 403，容易被误判为 WAF/鉴权在起作用。
# 对照：换 Host / 换路径 / 换 UA 各发一次；若全部返回同一个 403 页面
#      ⇒ 是端口级白名单（nginx default_server / 反代），不是应用鉴权。
curl -s -o /dev/null -w "%{http_code}\n" -H "Host: a.example"  http://<IP>:888/
curl -s -o /dev/null -w "%{http_code}\n" -H "Host: b.example"  http://<IP>:888/
curl -s -o /dev/null -w "%{http_code}\n" -H "Host: c.example"  http://<IP>:888/
# 若三者同码同页 → 该端口对所有业务域名统一 403，不存在"绕过后台"的价值。

## 对照 3 —— 假全开（中间防护设备对所有端口回 SYN-ACK）
# 现象：nmap 报一台机器十几个端口全 open（例如 21,22,80,443,888,3306,6379,8080,
#      9010,10004,10010,10013,27017,9200,11211），看着像"数据库全家桶"。
# 对照 A：对同一 IP 的随机高位端口做连接测试（12345 / 54321 / 65000）。
#        若随机端口也"可连接" ⇒ 前置设备对所有端口回 SYN-ACK，全开结论全部作废。
# 对照 B：对报 open 的端口做应用层交互（HTTP / 协议握手），无响应即证实为假。
foreach ($p in @(12345,54321,65000,22,80,6379)) {
  ":$p => " + (Test-NetConnection -ComputerName <IP> -Port $p -InformationLevel Quiet -WarningAction SilentlyContinue)
}
# 实测（假）：203.0.113.74 / 203.0.113.75 —— 12345/54321/65000 全部 True，
#            而 10010/9200/8080/888 应用层零响应 ⇒ "Redis/MySQL/ES/Mongo 未授权"这条路不成立。
# 实测（真）：203.0.113.78 / 203.0.113.67 / 203.0.113.86 —— 随机端口 12345 = False，
#            22 / 80 = True ⇒ 端口真实开放，可据此派活。
# 对照组务必混入"已知应关闭"的端口（随机高位端口），否则无法证伪。
