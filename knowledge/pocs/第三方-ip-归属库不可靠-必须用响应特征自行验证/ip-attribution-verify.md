# 第三方 IP 归属库不可靠：必须用响应特征自行验证

## 现象
第三方 IP 归属查询站（sojson / target60.example.com / boip 等）会把云厂商的 IP 标注成
**具体公司名**（例如"北京市 XX 网络科技有限公司"），看起来像是"该公司资产"。
实际这批 IP 可能只是**云厂商自己或其它租户的基础设施**，与查询的公司毫无关系。

## 实测反例（tgt9942 靶标）
- 依据：集权后台用户记录里读到运营主体 = 「北京市 驰骏网络科技有限公司」
- 第三方归属库把 6 个百度云 IP（203.0.113.51 / .110.74 / .166.67 / .201.156 / .201.211 / .64.68）
  全部标注为该公司 ⇒ 一度推断为"运营方正规业务/办公网资产"
- **验证**：对每个 IP 各发一次轻量请求
  `curl.exe -s -I -m 10 -A "<Chrome UA>" "http://<IP>/"`
- **结果**：`203.0.113.52` 返回 **302 → https://esg.baidu.com/**（百度自家服务），
  其余 5 个无响应 ⇒ **这批 IP 实为百度云自身基础设施**
- **结论**：归属库标注不可靠，「运营方办公网」假设撤销，避免误伤云厂商资产

## 规则
1. 归属库/WHOIS/ICP 的"公司名"标注只作**线索**，不作结论；
2. 判定归属必须看**响应特征**（Server 头、跳转目标、页面内容、证书 CN/SAN）；
3. 走云厂商 IP 段（182.61.x = 百度云、43.99.x = 腾讯云等）时默认怀疑：
   大概率是云厂商或其它租户，不是目标方；
4. 对"可能是无关第三方"的资产**只做一次轻量只读请求**，
   不做目录爆破、不碰登录口 —— 合规与误伤风险远高于打黑产站群；
5. 撤销结论时要显式写明"假设撤销 + 依据"，避免他人沿用错误前提。

## 反向正例（同一靶标）
`203.0.113.42`（集权后台 admin login_ip）经查询属 `AS140227`
（HKCICL-AS-AP 香港通信国际），该 ASN 同时出现在 ThreatFox 黑名单与
Cloudflare Radar 机器人流量榜 ⇒ 这是**独立第三方旁证**，可信度高于自建推断。
