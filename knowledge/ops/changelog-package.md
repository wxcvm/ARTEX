# ARTEX 0.4.1

## 内置 FOFA MCP（开箱即用）

不再需要 `npx` / `pip install` 装第三方 fofa-mcp —— 那些都依赖联网拉包，

而 ARTEX 是离线便携包。现在自带一个**只用标准库**的实现：

```

data/tools/mcp/fofa_mcp.py    9.7 KB，随包走

```

**首次启动自动注册**成一条真实的 MCP 记录（和 ScopeSentry / browser 同一片网格），

并**自动授权给 6 个 agent**：规划 / 执行 / 主 / 渗透测试 / Auto / 漏洞利用。

提供的工具：

| 工具 | 作用 |

| --- | --- |

| `fofa_search` | 按 FOFA 语法查资产（app/domain/cert/ip/title/body），返回表格 |

| `fofa_account` | 查账号剩余 F 点，配完先跑它确认 key 有效 |

你只需要填两个环境变量：`FOFA_EMAIL` / `FOFA_KEY`，然后开开关。

**平台差异**：Windows 包内含 python313 运行时，开箱即用；Linux/macOS 用系统

`python3`（绝大多数发行版自带）。缺 Python 时 MCP 页面会明确提示，不是静默消失。

# ARTEX 0.3.68

## agent 自主控制代理池策略

新增 host 工具 `proxy_pool_control`，把"要不要自动换 IP"的判断权交给 agent。

为什么让 agent 决定：这件事依赖任务性质，而 agent 执行时最清楚自己在做什么 ——

扫目录被封了继续换 IP 是对的，但打登录后台换 IP 会掉 session，

目标有 IP 白名单时换了直接进不去。

```

proxy_pool_control(action=status)    查看状态（出口 IP / 节点 / 开关）

                (action=auto_on)     开启封禁自动换 IP

                (action=auto_off)    关闭（需保持登录态/固定出口时）

                (action=rotate)      立刻换一条 IP

                (action=pin, node=X) 固定到指定节点

                (action=unpin)       解除固定

```

工具描述里写清了判断依据，agent 看到就知道何时该用哪个。

`auto_off` 只关自动轮换，不是关代理池 —— 流量照走，只是源 IP 不再变化。

`pin` 会连带关闭自动切换（否则"固定"名不副实），`unpin` 时自动恢复。

实测：给任务只描述目标、策略留空，agent 自己 `status` → 发现自动换 IP 是关的

→ `auto_on` → 再 `status` 复查确认，全程无人工干预。

## 封禁与被墙检测（0.3.67 基础上）

三类分治：

| 情况 | 判定 | 动作 |

| --- | --- | --- |

| 目标封禁 | 403/captcha/Access Denied/人机验证/网站防火墙 | 立刻切 |

| 连接被墙 | Connection reset / SSL_ERROR_SYSCALL / timeout | 连续 2 次才切 |

| 本地代理挂了 | 报错含 127.0.0.1:17890 | 不切，提示重启 |

单次失败不切，成功响应清零计数 —— 避免"今天零星失败两次"在几小时后误触发。

## 节点池耗尽告警

5 分钟窗口内切换次数达到节点数 → 判定轮完一圈仍被封，自动关闭切换并写明原因。

避免"切了又封、轮回到原点"却让 agent 以为 IP 已经换过。

## mihomo 进程守护

每 30 秒 Dial 探 API 端口，崩了自动拉起，退避 5s→15s→30s→60s，

连续 5 次失败才放弃。实测 kill 后 30 秒内恢复。

## 网关型代理池（0.3.67 基础上）

支持 CLIProxy / IPIDEA 这类「网关+账密」服务：账号 + 国家地区下拉 +

会话类型（粘性/轮换）+ 前置代理（mihomo dialer-proxy 链式转发）。

# ARTEX 0.3.67

## IP 代理池：网关型代理（CLIProxy / IPIDEA 这类）

新增第三种接入方式 —— 不再只支持机场订阅，商业住宅代理也能用：

```

池类型

  ├─ 机场订阅   贴订阅链接 → 解析 vmess/ss/trojan/vless

  └─ 网关账密   填网关+账号密码 → 生成 N 条独立出口 IP

```

网关型的原理：服务商靠**用户名里的参数**决定出口，

`acct-region-US-sid-abc-t-15` 里改 `sid` 就是换一条 IP。

平台用同一网关 + N 个不同 sid 生成 N 个 mihomo 节点，切节点即换 IP。

表单支持：账号 / 国家地区下拉（Rand+200 国）/ 会话类型（粘性·轮换）/

时长 / 节点数 / 协议 / **前置代理**。

**前置代理**是给「服务商拒绝大陆 IP 直连网关」准备的（CLIProxy 就是），

填一个能出国的本地代理即可，走 mihomo 的 dialer-proxy 链式转发。

## 封禁与被墙：现在都会自动换 IP

之前只检测「被封」（403/captcha/WAF 页文字），**被墙完全不可见** ——

连接被重置、超时、SSL 中断这些输出里没有可匹配的文字，

agent 会在断网状态下白跑几十条命令。

现在分三类处理：

| 情况 | 判定 | 动作 |

| --- | --- | --- |

| 目标封禁 | 403/captcha/Access Denied/人机验证/网站防火墙 | 立刻切 |

| 连接被墙 | Connection reset / SSL_ERROR_SYSCALL / timeout 等 | **连续 2 次**才切 |

| 本地代理挂了 | 报错里带 127.0.0.1:17890 | 不切（换多少都一样），提示重启 |

单次失败不切 —— 节点抖动会造成误判，按次切会把池子瞬间耗光。

另外补了 `curl -w "%{http_code}"` 的输出识别：agent 探测最常用这条命令，

输出是裸的 `403`，之前匹配不上短语，属于最常见的漏检。

## 节点池耗尽告警

自动切换只能解决"某条 IP 被封"，解决不了"整个池子都被封"。

后者表现为切了又封、轮一圈回到原点，agent 却以为 IP 已经换过。

现在：5 分钟窗口内切换次数达到节点数 → 判定耗尽，**自动关闭切换**并写明

「节点池可能已全部被封，建议换国家/地区或换服务商」。

## mihomo 进程守护

mihomo 崩溃后 `running` 标记不会自动变，界面还显示"运行中"。

现在：

- 每 30 秒用 Dial 探 API 端口（TIME_WAIT 不会误判）

- 崩了自动拉起，指数退避 5s→15s→30s→60s

- 连续 5 次失败才放弃并写明原因

实测：手动 kill 后 **30 秒内自动恢复**。

## 出口探测不再阻塞界面

原来出口探测同步跑，一次最坏 6 目标 × 8 秒，把 HTTP 接口拖到几十秒，

前端 5 秒轮询直接堆积。

现在改成异步：接口立即返回缓存值，探测在后台跑。

实测连续请求从 **25 秒超时 → 1.8ms**。

失败原因也做了分级：前置代理不可达会说"请确认那个客户端在运行"，

前置正常则提示检查服务商余额/白名单。

## 安全

- 网关密码不再回传前端（之前每次打开页面都明文送到浏览器）

- `config.yaml` 显式 `chmod 600`（之前对已存在文件不生效，Linux 上等于同组可读）

## 其他

- 机场公告节点过滤（「剩余流量：xxx」「套餐到期」「过滤掉 N 条线路」这类

  假节点会占位、拖慢测速、被自动切换选中）

- 拉订阅时重置池类型（之前从网关切回订阅会出现 kind=gateway 配订阅节点的错乱）

- 停止再启用时恢复原有全局代理（之前直接变直连）

# ARTEX 0.3.67

## IP 代理池：支持 SS / Trojan / VLESS

0.3.66 只解析 `vmess://`，导致一类常见机场（自由猫、守候、糖果云等

主打 Shadowsocks / Trojan / VLESS 的）订阅进来会提示"没有解析出可用节点"，

而且看不出是协议不支持。这版补齐：

| 协议 | 支持的 URI 形态 |

| --- | --- |

| vmess | v2rayN JSON 风格 + Shadowrocket 风格 |

| ss | `base64(method:password)@host:port`、整段 base64（旧版）、明文、带 obfs / v2ray-plugin |

| trojan | `password@host:port?sni=&type=ws&path=` |

| vless | `uuid@host:port?security=tls\|reality&type=ws\|grpc&...` |

传输层统一处理 `type=ws/grpc/h2/tcp`、`security=tls/reality`、

`sni` / `host` / `path` / `serviceName` / `alpn` / `fp`（Reality 公钥 `pbk` + `sid`）。

**一个容易踩的坑**：Trojan 协议本身就跑在 TLS 上，分享链接里通常不写

`security=tls`。但 clash 配置要求显式 `tls: true`，漏了会按明文握手直接连不上。

解析器现在对 trojan 默认开 TLS。

## 其他

- `parseSubscription` 支持混合协议订阅（SS + Trojan + VLESS + vmess 混在一起）

- 加了一组解析器单测（9 个用例覆盖四种协议的真实 URI 形态 + 垃圾输入拒绝）

# ARTEX 0.3.66

## 新功能：IP 代理池

左侧菜单「功能 → IP 代理池」。贴一个机场订阅地址，自动解析出节点，

agent 跑任务时遇到目标封 IP 会自动换下一个。

### 怎么用

1. 贴订阅地址（支持 Shadowrocket / Clash 的 base64 订阅），点「拉取」

   　→ 只解析节点，不改任何设置，可以先看清有多少节点

2. 点「启用」

   　→ 内置 mihomo 启动，把本地 SOCKS5 注册成出口，`global_proxy` 指向它

   　→ 所有任务的目标流量开始走代理池

3. 需要时点「测速」「换一个」，或点某个节点后面的「用这个」手动固定

### 自动切换的两层机制

- **mihomo 层**：url-test 策略组每 60 秒测延迟，节点挂了自动挑最快的

- **ARTEX 层**：Bash 输出命中封禁特征（403 / 429 / Access Denied / 人机验证 /

  安全狗 / 云锁 等）时，立即切到下一个可用节点。agent 看到 403 会自己重试，

  那时源 IP 已经换了

两层都开（可以在页面关掉第二层）。手动固定节点时不会自动切——

用户明确指定了用哪个 IP，擅自换掉会让人摸不着头脑。

### 实现说明

- 内置 mihomo（Clash.Meta 内核）作为协议转换层：订阅里的 vmess/vless/trojan

  节点由它转成本机 SOCKS5/HTTP（127.0.0.1:17890）

- 每个平台的包只带自己那份 mihomo（约 30MB），不塞全平台

- 代理池关闭时 `global_proxy` 清空，退回直连

- 服务重启会恢复上次状态；mihomo 拉不起来就自动退回直连，

  避免全流量打到一个死端口

### 已知限制

- 手动固定节点时不参与自动切换（见上）

- 节点名重复时会用第一个（订阅里常有「剩余流量」「套餐到期」这类占位节点）

# ARTEX 0.3.65

## 安全加固（重要）

这一版针对「部署到公网后被滥用」的问题做了三件事。起因是一台公网 VPS 实测

跑两个月后暴露出的真实风险：

- SSH 累计 **6.4 万次** 暴力破解尝试，还出现过陌生 IP 的 root 会话（挂 22 小时）

- 渗透测试期间 agent 起了 **70+ 个** 监听端口，全部绑 `0.0.0.0`、无鉴权、对公网可达

- `config.json` 里数据库口令权限过宽，`/tmp` 被 PT 脚本写满

### 1. 随包提供 `harden-server.sh`

新部署的 Linux / macOS 包根目录多了这个脚本：

```bash

sudo bash harden-server.sh --yes

```

它做四件事，全部可回滚：

- SSH：开启密钥登录、禁用密码登录、`MaxStartups` 放宽到 `30:50:200`

  （默认值在连接多时会随机丢包，表现为"能连但卡住不动"）

- 防火墙：封掉 ARTEX 内部代理端口（1080/9050/19446 等），SSH 加限速

- 权限：`config.json` 收紧到 600

- 清理：装定时任务清理 7 天前的 PT 临时脚本

**安全设计**：脚本检测到 `authorized_keys` 里没有公钥时，会自动跳过

"禁用密码登录"，不会把操作者锁在门外。

### 2. 给 8 个执行类 agent 补「测试服务规范」

worker / worker.intranet / exploit / pentest / mainagent / avevasion / cloud / auto

现在都明确要求：

- 测试服务默认绑 `127.0.0.1`，只有 OOB 回连等确实需要外部访问时才绑 `0.0.0.0`

- 对外端口要在 fact 里登记（端口/用途/何时关）

- 测完立刻关闭监听，收尾时检查 `ss -lntp | grep -v '127.0.0.1'`

- **口令不写在命令行里**（`ps` 和 bash history 可见），改用环境变量或配置文件

### 3. 部署文档补安全说明

`install-deps.sh` 结尾和 `README-linux.txt` 都提示了公网机器要跑加固脚本。

## 一、对话撤回

对话和任务主会话的输入框右侧、发送键左边多了一个 `↩` 按钮。

**点一次撤回一轮**：

```

① 最后一条你发的消息被删掉

② 它之后的所有模型回答、工具调用、token 统计一起删掉

③ 那条消息的正文自动填回输入框

④ 附件挂回待发列表

⑤ 界面立刻回到"没发过"的状态，不用刷新

```

**模型也真的忘掉**——不只是界面上消失。撤回会同步回退 SDK 的会话记录（`transcripts/*.jsonl`），下次提问时模型读到的上下文里没有那一轮。

两处都有：

| | 位置 |

| --- | --- |

| 独立对话 | 对话页输入框右侧 |

| 任务主会话 | 任务详情 → 会话 → 主 Agent 输入框右侧 |

主 Agent 正在回答时按钮不可点（要先停止），否则模型还在往记录里追加内容，删了会长回来。

## 二、代理与出口 IP

### 多出口 IP 管理

系统配置新增「出口 IP」：录入多条代理（名称、地址、备注），任意切换当前生效那条。

```

系统 → 系统配置 → 出口 IP

  ├── 直连

  ├── 出口 A（http://...）

  ├── 出口 B（socks5://...）

  └── ...

```

切换后全平台出站流量（扫描、探测、抓包代理）立即走新出口，不用重启。每条可单独测连通性，显示实际出口 IP 与延迟。

### 导航栏出口状态横幅

顶部导航栏中间显示当前出口状态：

| 颜色 | 含义 |

| --- | --- |

| 红 | 直连，未使用代理 |

| 绿 | 已走指定出口，显示实际出口 IP |

| 黄 | 代理不通，或代理没改变出口（仍是本机 IP） |

点击展开出口列表直接切换。做多目标、多身份时，一眼看清"我现在从哪个 IP 出去"。

## 三、漏洞管理

### 漏洞复现步骤

漏洞记录新增结构化「复现步骤」字段，与自由文本的「证据」分开：

```

入口 URL：    http://target/login

前提条件：    需要能访问 /login

步骤 1：      POST /login  username=admin' or '1'='1

              响应 302 → /dashboard

              证明：注入绕过了认证

步骤 2：      ...

```

导出报告时按步骤渲染，可复制成命令直接重放。Agent 上报时若证据里有 HTTP 痕迹但复现步骤为空，工具调用会被退回要求补全。

### 报告撰写 Agent 下线

原「报告撰写」角色移除，Agent 数量 17 → 16。挖到漏洞时由执行 Agent 直接写完整记录，验证由 `verifier` 负责。

## 四、知识库

### 手动新增条目

知识库页面支持手工录入 POC/EXP，走表单提交，不必依赖 Agent 自动沉淀。

### 入库员 Agent

新增 `kb_curator`，负责把任务中挖到的东西沉淀进库：查重、归类、规范化后落库。

### 整目录可迁移

知识库落盘改为相对存储并兼容旧绝对路径，整个目录拷到另一台机器仍能读正文。

## 五、任务与 Agent

### 破甲预设

系统配置内置 4 套「破甲」预设，可一键应用到指定 Agent。

### 拦截规则

Agent 执行敏感动作前的拦截策略，内置 8 条（隧道裸跑、横向执行、口令爆破、域枚举等），可增删改。命中的动作进「审批记录」，可放行或拒绝。

### 每任务触发上限

限制单个任务内由触发器拉起的专家 Agent 次数，防止一个任务无限拉起子 Agent 拖垮资源。

### 暂停/恢复

任务暂停时取消该任务已拉起的触发式专家会话，暂停期间丢弃新的触发。恢复后不会有一堆积压的旧触发同时启动。

### 专家取消

任务运行中可单独终止某个专家 Agent，不影响主任务。

登录页品牌标识、侧边栏菜单重命名、首次初始化的密码设置页文案统一。

## 七、工具链

### 随包工具自动登记

启动时扫描随包工具目录，自动注册到工具库，Agent 可直接按绝对路径调用。

**Windows 版**带 27 个（nuclei、ffuf、naabu、subfinder、impacket 全套、冰蝎、哥斯拉等）。

**macOS / Linux 版**带 12 个：

外加冰蝎 / 哥斯拉 / OneForAll / linpeas 放 `redteam/toolkit/`。

### 工具路径分平台适配

Windows 用 `nuclei.exe`，macOS / Linux 用 `nuclei`。启动时按平台自动补扩展名。

## 八、部署

### 忘记密码可自救

包根多了重置工具：

```

Windows       重置密码.bat（配 scripts\reset-password.ps1）

macOS/Linux   reset-password.sh

```

密码以 bcrypt 哈希存在数据库里，取不回明文，但可以清掉重设。脚本会自己从 `config.json` 读库密码和端口，先检查数据库在不在线。

```

1. 启动服务（数据库要在线）

2. 跑重置脚本，输入 Y 确认

3. 重启服务

4. 打开页面，会要求重新设置密码

```

### 后台运行

ARTEX 与 PostgreSQL 均以无窗口方式启动，关闭启动窗口不影响服务。

### 默认配置随包分发

破甲开关、破甲预设、拦截规则、Agent 提示词、系统设置等出厂默认值随包携带，首次启动自动应用一次。之后在界面修改的设置持久保存，重启不覆盖。
